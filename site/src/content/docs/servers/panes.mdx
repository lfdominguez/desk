A pane is a real terminal: a shell on one server, over desk's own SSH client (no `ssh` program
runs; see [How desk connects](/servers/servers-file/#how-desk-connects)). You type in it, and so
does the tab's infra Claude. The output stays: every command becomes a numbered block.

![A pane on web-02 with four command blocks Claude ran, and the Claude panel beside it](../../../assets/shots/srv-turn1.png)

## The pane's header

<figure class="cut">

![The header of web-02's pane: a green dot, web-02, 192.0.2.12, "□ screen off", "click #n to pin · ⇧ copies its output · ⌃⇧↑ picks" and a ×](../../../assets/shots/srv-workspace-pane-head.png)

<figcaption>The server, its address, the screen toggle, a reminder of the block keys, and ×.</figcaption>
</figure>

- The dot is green once the server answered, orange while it hasn't.
- A **Claude** pill means Claude opened this pane. A **typing into every pane** pill means
  [broadcast](#broadcast) is on.
- The **screen** toggle (on the focused pane) decides whether Claude gets a snapshot of the
  screen with your question:
  - **screen off**: only when it looks needed (see [What Claude sees](#what-claude-sees)).
  - **screen**: with the next question. <kbd>Ctrl</kbd>+<kbd>Shift</kbd>+<kbd>S</kbd> does the same.
  - **screen auto**: shown while a full-screen program (`htop`, `vim`, `less`…) runs; the
    screen goes along by itself.
- **×** closes the pane, like <kbd>Ctrl</kbd>+<kbd>Shift</kbd>+<kbd>W</kbd>.

## More panes

<kbd>Ctrl</kbd>+<kbd>Shift</kbd>+<kbd>T</kbd>, or the toolbar's first button, opens another pane
on the focused pane's server, in the same tab. Panes stack top to bottom.

![Two panes on web-02 in one tab, one above the other](../../../assets/shots/srv-split.png)

- All panes of a server share one SSH connection (the files split, Claude's `changes` tool and
  port forwards use it too), so a new pane opens at once, with no second login. It stays a
  minute after the last of them closes.
- Click a pane to focus it. With more than one, the focused pane has an accent outline.
- <kbd>Ctrl</kbd>+<kbd>Shift</kbd>+<kbd>W</kbd> closes the focused pane. On a tab's last pane it
  closes the tab.
- Claude can open panes too (for a long-running command while it checks something else). It
  can close only the panes it opened.

## Command blocks

desk adds a small shell integration to bash, zsh and fish when the first prompt shows, then
clears the screen, so the line it typed doesn't stay there. That clear also removes what the
server printed at login (its banner and message of the day); turn on **Show the server's login
message** in the organization's settings (or put `clear_login = false` at the top of its
`desk.toml`) to get that text back above the first prompt, as plain text. From
then on each command you or Claude run becomes a **block**, numbered from #1 in the gutter.
On Windows, the local pane runs PowerShell (`pwsh` when it's on your `PATH`, else Windows
PowerShell), which gets blocks and keeps its folder and environment variables over a restart too:

<figure class="cut">

![Blocks #1 to #4 on web-02; each shows "Claude", a green ✓ 0 or a red ✗ 3, and its duration](../../../assets/shots/srv-turn1-blocks.png)

<figcaption>Each block: its number, the command and output, who ran it, its exit code and how long it took.</figcaption>
</figure>

- The badges on the right show the duration, **✓ 0** or **✗** and the exit code, **Claude** when
  Claude ran it, **pinned** when you pinned it, and **running** while it runs.
- **Click #n** to pin the block: it goes to Claude with your next question. Click again to unpin.
- **⇧+click #n** copies the block's output ("Copied the output of #n").
- <kbd>Ctrl</kbd>+<kbd>Shift</kbd>+<kbd>↑</kbd> and <kbd>↓</kbd> pick a block from the keyboard.
  The header then reads "block #n · space pins · y copies · ↑↓ · esc":
  - <kbd>Space</kbd> pins it, <kbd>Y</kbd> copies it, <kbd>↑</kbd>/<kbd>↓</kbd> move to the
    next one.
  - <kbd>Esc</kbd> or <kbd>Enter</kbd> stops picking. Any other key stops and goes to the shell.

Every finished block is also written to the [audit log](/servers/infra-claude/#the-audit-log).

### What Claude sees

When you ask Claude something, desk sends the blocks you point at:

- The blocks you pinned.
- Any `#n` in your question ("why did #3 fail?").
- "last N" in your question ("look at the last 2").
- With none of those, the last 3 blocks.

It also sends a snapshot of the screen when you turned **screen** on, when a full-screen program
is running, or when your question mentions the screen, a snapshot, `top` or `htop`.

## Scrollback, find and copy

- Each pane keeps 10,000 lines of scrollback. The mouse wheel scrolls it, unless a full-screen
  program asked for the mouse.
- <kbd>Ctrl</kbd>+<kbd>Shift</kbd>+<kbd>H</kbd> opens **Find in scrollback**, with the same
  [fzf syntax](/board/search/) as the board. Typing jumps to the newest match; **↵** goes to
  the next older one; **esc** closes. It shows "N of M", "no matches" or "type to search".
- **Drag** to select: it's copied when you let go ("Copied").
- **Double-click** selects a word (a path, a URL or a `host:port` counts as one word);
  **triple-click** selects the line.
- <kbd>Ctrl</kbd>+<kbd>Shift</kbd>+<kbd>C</kbd> copies the selection and
  <kbd>Ctrl</kbd>+<kbd>Shift</kbd>+<kbd>V</kbd> pastes.

## Resizing

Make the window, the Claude panel or a pane bigger or smaller and the terminal follows: the
server gets the new size, and lines rewrap to the new width, with the blocks and prompts moving
along with them. Text from a restored session or a reconnect is rewrapped at the pane's width
too.

The text size does the same: <kbd>Ctrl</kbd>+<kbd>=</kbd> bigger, <kbd>Ctrl</kbd>+<kbd>-</kbd>
smaller and <kbd>Ctrl</kbd>+<kbd>0</kbd> back to 100%, in a pane or anywhere in desk (see
[Settings](/orgs/settings/#text-size)). The shell doesn't get those keys.

## Broadcast

The toolbar's second button (the fan) types into **every pane of the tab** at once: keys and
paste go to all of them. It's for running the same thing on several panes of a server side by
side.

<figure class="cut">

![The toolbar with the broadcast fan button on](../../../assets/shots/srv-broadcast-toolbar.png)

<figcaption>The broadcast button, on.</figcaption>
</figure>

- It needs two or more panes ("broadcast needs two or more panes").
- While it's on, each pane has an orange outline and the pill **typing into every pane**.
- Click the button again, or pick **broadcast typing to all panes** in the
  [palette](/servers/palette/), to stop.

## The connection box

While a pane's connection isn't up, a box over it says what's going on and what you can do.

### Connecting, step by step

When a pane opens a new connection to a server, the box shows each step as it happens, with its
time (milliseconds under a second, then seconds): reading the config, looking up the host name,
connecting to its address (or the jump host's steps, prefixed `via <host>:`, or the
ProxyCommand), exchanging keys, checking the host key, each authentication method tried (with
the vault's password looked up only when the server asks for a password), starting the forwards
and opening the shell. A wait on you (a
passphrase, a password, a "yes/no") is its own step, in grey, so it doesn't read as network time.
After 10 seconds the box adds that a VPN may be down; **Close** (<kbd>C</kbd> or <kbd>Esc</kbd>)
closes the pane.

Once the shell is up the box goes, and the pane's header reads "connected in 2.4 s" until its next
connection; hover it for the steps and the total, with the part spent waiting for you apart. A
step that fails is marked with its time, and the box below says why.

A pane that shares a connection already open to that server (a second pane, the files panel) has
no steps: it didn't connect.

### Not answering yet

If a pane that shares a connection still being made hasn't heard from the server after 10
seconds:

<figure class="cut">

![web-01 isn't answering yet. 12s and counting. A VPN may be down. Close C, Keep waiting W](../../../assets/shots/srv-timeout-box.png)

<figcaption>The server hasn't answered in 10 seconds.</figcaption>
</figure>

- **Keep waiting** (<kbd>W</kbd> or <kbd>Enter</kbd>) gives it another 10 seconds.
- **Close** (<kbd>C</kbd> or <kbd>Esc</kbd>) closes the pane.

### Couldn't connect

When the connection ends before the shell started:

<figure class="cut">

![Couldn't connect to db-01, with the error "ssh: connect to host 192.0.2.21 port 22: No route to host", Close pane C and Reconnect R](../../../assets/shots/srv-failed-box.png)

<figcaption>Why it failed, and what to try.</figcaption>
</figure>

- The box shows why (the error is printed in the pane too) and "Tried N times" when desk retried.
- **Reconnect** (<kbd>R</kbd>) tries again. The scrollback stays as it was.
- **Close pane** (<kbd>C</kbd>) closes it.
- **Fix algorithms** (<kbd>F</kbd>) shows up when the server offers only algorithms modern SSH
  turns off ("Unable to negotiate: no matching KexAlgorithms found. Their offer: …"). It adds
  them to that host in its ssh_config (`KexAlgorithms +diffie-hellman-group1-sha1`,
  `HostKeyAlgorithms +ssh-rsa`…) and reconnects. Algorithms desk doesn't have at all (`ssh-dss`
  keys on a server that offers nothing else) can't be fixed this way.
- When the server's host key changed, the box shows both keys instead.
  See [A changed host key](/servers/host-keys/).

### Reconnecting

A link that drops after it was up (a laptop asleep, a VPN down) comes back on its own:

- The pane's text gets "── connection lost at 14:32:07, reconnecting ──".
- The box reads "Reconnecting to web-01…", with how long ago it dropped and when the next try is.
  **Retry now** (<kbd>R</kbd>) doesn't wait.
- desk retries every 2 seconds at first, backing off to 30, for 5 minutes. Then it shows
  **Couldn't connect**.
- Port forwards on that server come back once it's up again.

### Passwords for ssh

On the first password the server asks for, desk answers from the vault when the server has a
[`#@ password`](/servers/servers-file/#vault-password-and-password-raw); the vault isn't read
before then, so a server your key logs into never waits on it. Otherwise, or for
anything else the connection asks (a key's passphrase, a keyboard-interactive question, a new
host's "yes/no"), a box asks you: "ssh web-01 asks", with "Sent to this ssh session only, not
stored." Your answer goes to that connection only, and Claude never sees it. A vault password the
server rejected is said so with the next question ("(the vault password was rejected)").

If the vault is locked, desk asks for its password first ("Unlock …"). That password is kept in
memory only.

## sudo passwords

When a pane waits at a password prompt (`sudo`, `doas`, `su`, "Password:"), a bar above the
prompt reads "Asks for deploy's password" with **Type server password**
(<kbd>Ctrl</kbd>+<kbd>Shift</kbd>+<kbd>P</kbd>).

- It types the server's password from its `#@ password` (or `password-raw`) straight into the
  prompt: "sudo password sent".
- With no prompt waiting, the same key copies the password instead: "server password copied".
- With no password set for the server, the bar says so ("no #@ password for this server").

## Wake-on-LAN

A server with [`#@ wol`](/servers/servers-file/#wol) gets a magic packet each time a pane
opens on it, just before desk connects. desk doesn't wait for it to boot: if the pane says the
server isn't answering yet, give it time (or **Keep waiting**, when the box offers it).

## Recordings

Every pane is recorded, from connect to close, as an [asciicast](https://docs.asciinema.org/manual/asciicast/v2/)
file you can play back:

```sh
asciinema play ~/.local/state/desk/infra/recordings/Globex/2026-11-04-143207-web-02.cast
```

- One file per pane and connection, in `~/.local/state/desk/infra/recordings/<Org>/`, named by
  the date, time and server.
- They're kept 7 days, and at most 1 GiB per organization; older ones go first.
- **Open recordings** in the [palette](/servers/palette/) opens the folder.
- To turn recording off for an organization, put `record = false` at the top of its `desk.toml`.

:::caution
A recording holds everything the pane showed. Treat the folder like the servers' own logs.
:::
