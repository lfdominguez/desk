## nix run off NixOS

On Ubuntu, Fedora and other distributions, builds of desk older than 2026.11.04 fail to open a window under `nix run github:lfdominguez/desk`:

```
desk: vulkan: libvulkan.so.1: cannot open shared object file: No such file or directory
```

desk tries OpenGL (EGL) first and Vulkan second, and only the last error shows. nixpkgs' graphics libraries look for GPU drivers only in `/run/opengl-driver`, which only NixOS has.

The flake's `desk` wrapper handles this. When `/run/opengl-driver/lib` is missing, it points the EGL, DRI and GBM loaders at nixpkgs' own Mesa:

```sh
__EGL_VENDOR_LIBRARY_FILENAMES=<mesa>/share/glvnd/egl_vendor.d/50_mesa.json
LIBGL_DRIVERS_PATH=<mesa>/lib/dri
GBM_BACKENDS_PATH=<mesa>/lib/gbm
```

- **Intel, AMD, nouveau**: Mesa drives the GPU, and desk runs normally.
- **NVIDIA's own driver**: Mesa can't drive it, so desk falls back to llvmpipe, Mesa's software renderer. It works, but uses the CPU to draw. For GPU drawing, install the [AppImage or .deb](/start/install/), which use your system's driver, or point the variables above at your driver yourself: a value you set wins over the wrapper's.

On NVIDIA, the terminal shows lines like these as desk starts:

```
MESA-EGL: warning: pci id for fd 15: 10de:2f04, driver (null)
MESA-EGL: warning: egl: failed to create dri2 screen
```

They are harmless. `10de` is NVIDIA's PCI vendor id, and `driver (null)` means Mesa has no driver for that card. Mesa tries each GPU device, gives up on the NVIDIA ones, and settles on llvmpipe. If desk's window opens, you can ignore them.

## Wayland only

On Linux, desk needs a Wayland session (Hyprland, Sway, KDE, GNOME…). It's built without X11 support, so it doesn't open under an X11 session. X11 support is on the roadmap.

## macOS

- **"desk.app cannot be opened because Apple cannot check it".** The release's app is ad-hoc signed, not with an Apple Developer ID, so Gatekeeper stops it the first time. Right-click it in Finder, choose **Open**, then **Open** again, or run `xattr -dr com.apple.quarantine /Applications/desk.app` once. "desk.app is damaged and can't be opened" is the same quarantine flag on a copy that lost its signature: the `xattr` command fixes it too.
- **Sessions fail with `claude` not found.** An app opened from Finder or the Dock doesn't get your terminal's `PATH`, only the system's (`/usr/bin:/bin:/usr/sbin:/sbin`), so `claude` in `~/.local/bin` or `/opt/homebrew/bin` is out of reach. desk reads the `PATH` of your login shell (`$SHELL -l`) at start, so whatever your shell's profile adds is found. If your profile only sets it for interactive shells (fish's `if status is-interactive`, zsh's `.zshrc`), move that line to the login part (`config.fish` outside the block, `.zprofile`).
- **No notifications.** macOS delivers them only to an app bundle: run `desk.app`, not a bare `desk` binary (a `go build`, or `nix run`). The first one asks for permission; if you said no, allow desk in System Settings → Notifications.
- **desk quits as it opens, in a virtual machine.** desk draws with the GPU through Metal. A macOS VM without a virtual GPU (a plain 800×600 display, "No Kext Loaded" under Graphics/Displays in System Information) has no Metal, and desk can't open its window there.
- **The virtual camera is missing.** Sharing a terminal as a webcam needs PipeWire and v4l2loopback, which are Linux-only; the rest of the infra workspace works.

## Windows

- **"Windows protected your PC".** The MSI and `desk.exe` aren't code-signed, so SmartScreen stops them the first time. Click **More info**, then **Run anyway**. A browser may also flag the download as "not commonly downloaded": keep it from the download's menu. If Windows only says the file "was blocked", open its **Properties** and tick **Unblock**, or run `Unblock-File .\desk-*-windows-amd64.zip` in PowerShell before unzipping.
- **`desk peer` is "not recognized" in your own terminal.** desk puts its own folder first on `PATH` for everything it starts, so its sessions find `desk peer` from the MSI or the portable zip alike. To type `desk` in a terminal of your own, it has to be on your `PATH`: the MSI adds its folder, `%LOCALAPPDATA%\Apps\desk` or `Program Files\desk` (terminals opened before the install don't see it until they restart); with the zip, add its folder to your user `PATH`.
- **Sessions fail with `claude` not found.** desk runs `claude` from `PATH`: check `where.exe claude` in a new terminal, and restart desk after installing Claude Code.
- **The virtual camera is missing.** Sharing a terminal as a webcam needs PipeWire and v4l2loopback, which are Linux-only; the rest of the infra workspace works.

## $SHELL points at a shell that isn't there

Some launchers set `SHELL=/bin/bash`, and on NixOS there's no `/bin/bash`. Everything desk runs inherits `SHELL`: ssh runs a host's `ProxyCommand` and `ProxyJump` with it, and Claude Code runs its Bash tool with it. A missing shell broke them.

desk fixes this at start. If `$SHELL` isn't a file, desk replaces it with the shell of the same name on your `PATH`, else with `bash`. If it finds neither, it leaves `SHELL` as it is. You don't need to do anything.

## An organization's sessions fail to start (bwrap)

An organization with a Claude profile (`~/Secure/Claudes/<Org>/`) runs its sessions inside `bwrap`, so they see that profile as `~/.claude`.

- **bwrap not installed.** desk looks for `bwrap` on your `PATH` (and in the Nix store). Without it, the session doesn't start and desk says `profile <Org> needs bwrap`. Install bubblewrap (`bubblewrap` on Debian, Ubuntu, Fedora and Arch).
- **bwrap fails.** bwrap needs unprivileged user namespaces. If your system restricts them (some distributions do, through AppArmor or a sysctl), bwrap exits at once: the card turns **failed**, and its line and conversation show bwrap's own error. Allow user namespaces for bwrap, following your distribution's documentation.
- **To run without a profile**, move the organization's folder out of `~/Secure/Claudes/`. Its sessions then use your own `claude` login, without bwrap.

On macOS and Windows there is no bwrap: a profile's sessions run `claude` with `CLAUDE_CONFIG_DIR` at the profile folder, and none of the above applies.

## Pasting an image does nothing

On Linux, <kbd>Ctrl</kbd>+<kbd>V</kbd> of an image reads the clipboard straight from the compositor, through the Wayland data-control protocol (`ext-data-control` or wlroots' `wlr-data-control`). Hyprland, Sway, other wlroots compositors and KDE have it. On macOS, <kbd>⌘</kbd>+<kbd>V</kbd> reads the pasteboard's PNG or TIFF image. On Windows, <kbd>Ctrl</kbd>+<kbd>V</kbd> reads the clipboard's PNG (what browsers copy), else its bitmap (screenshots, the Snipping Tool).

On a compositor without it, desk can't see the image, and <kbd>Ctrl</kbd>+<kbd>V</kbd> pastes the clipboard's text (if any) without an error. Save the image to a file and put its path in the message instead.

## A link says "no GitHub account"

desk only asks a provider through an account. A link whose organization has no account for its host and owner (or whose account has no token) says **no GitHub account** (or **no GitLab account**, **no Bitbucket account**). desk never fetches it, and its CI stays out of the CI view. It doesn't make anonymous calls: they'd see no private repositories and run out fast (GitHub allows 60 an hour per address).

To fix it, add an account to the card's organization in **Settings**, or in its `desk.toml`:

- `owners` must include the repository's owner (or be left out, for all owners).
- Its token must resolve. A `token_env` naming an unset variable is an error, not an empty token.

Then **Reload** in the sidebar rechecks every link. See [desk.toml](/reference/desk-toml/#github).

A card's **Ticket** switch needs somewhere to create the ticket. Without one, desk says `no tracker to create it in: give a Jira account projects, or a GitHub account a repo, in desk.toml`.

## desk asks for a vault's master password

When a token comes from a Bitwarden, Vaultwarden or Passbolt vault, desk asks for the master password (or the Passbolt key's passphrase) the first time a link needs it: the **Unlock** dialog, also on the toolbar. The password stays in memory only, never on disk, until desk quits. So desk asks again after each start.

- **Not now** (<kbd>Esc</kbd>) leaves the vault locked. The links that need it wait; unlock later from the toolbar.
- **A one-time code** is asked for too when the account has two-factor login. "Wrong or expired code, try the next one" means the code timed out: type the next one.
- **To stop being asked**, give the vault a `password` in `desk.toml` (for example `password = { token_env = "BW_PASSWORD" }`). For Bitwarden, an API key (`client_id` and `client_secret`) skips the two-factor code.

## A server's host key changed

A reinstalled server, or one whose keys were rotated, sends a key your `known_hosts` doesn't have for it, and desk refuses to connect. The pane's box then says **\<server\>'s host key changed** and shows the key the server sent next to the one in your `known_hosts`, by fingerprint.

- If you expected it, **Accept new key** (<kbd>A</kbd>). desk drops that line from `known_hosts`, saves the key shown and reconnects. It does nothing if the line no longer holds that key for that host.
- If you didn't expect it, don't accept. Someone may be in between. **Close pane** (<kbd>C</kbd>).

More in [Host keys](/servers/host-keys/).

## A server pane says "isn't supported by desk" or "which desk doesn't support"

desk connects with its own SSH client, not the `ssh` program, and a few things ssh does it
doesn't: GSSAPI (Kerberos) and host-based authentication, `PKCS11Provider` smart cards, FIDO
(`sk-…`) keys outside an agent, X11 forwarding, compression, `Tunnel`, `ProxyUseFdpass`. An
option it can do without prints "… isn't supported by desk; ignored" in the pane and the
connection goes on; a login that needs one fails, naming it. Use an agent for FIDO keys (`ssh-add`
them, `IdentityAgent` or `SSH_AUTH_SOCK`), or a password or key for the others. The full list:
[How desk connects](/servers/servers-file/#how-desk-connects).

## "Unable to negotiate: no matching … found"

The server offers only old algorithms desk leaves off unless asked. The pane's box has **Fix
algorithms** (<kbd>F</kbd>), which adds the needed `KexAlgorithms +…`, `HostKeyAlgorithms +…`,
`Ciphers +…` or `MACs +…` line to that host's block in the servers file and reconnects. Without
the button, the server offers nothing desk has (DSA host keys only, for one).

## desk peer says desk is not running

`desk peer` talks to a running desk through its socket in `$XDG_RUNTIME_DIR/desk/peer/` (`~/.cache/desk/run/peer/` on macOS and Windows). If it says `desk is not running. Ask the user to start desk, then try again.`, start desk. A session running with a different `XDG_RUNTIME_DIR` (another user, a container) can't reach it.

## desk crashed

desk runs detached, with no terminal to print to. A crash's trace goes to `~/.local/share/desk/crash.log`. Include it when you [report the bug](https://github.com/lfdominguez/desk/issues).

## The window vanished and came back

On Wayland the compositor can drop a window, for example when a monitor powers off to save energy and comes back. desk then opens its window again, every second until it can, with the board and sessions as they were; it gives up and exits after ten minutes. `crash.log` gets a `window lost, reopening:` line with the reason the display gave (a `protocol error … on <object>` names what the compositor rejected). Include it when you report the bug.
