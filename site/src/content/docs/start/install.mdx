## Requirements

- **Linux under Wayland** (Hyprland, Sway, KDE, GNOME and other Wayland compositors; X11 is on the roadmap), **macOS 12 or later** (Apple silicon or Intel), or **Windows 10 or 11** (x64).
- **[Claude Code](https://docs.anthropic.com/en/docs/claude-code)**: the `claude` command on your `PATH`, or where its native installer puts it (`~/.local/bin`, on Windows `%USERPROFILE%\.local\bin\claude.exe`). Every card runs it.
- **Optional, on Linux: `bwrap`** ([bubblewrap](https://github.com/containers/bubblewrap)). It lets an organization's sessions run under that organization's own Claude account. Without it, every session uses your own login. macOS and Windows need nothing for that: there each profile is handed to Claude Code as `CLAUDE_CONFIG_DIR`.
desk talks to GitHub, GitLab, Bitbucket, Jira, Nagios, the password vaults and your servers (SSH) itself. You don't need `gh`, `glab`, `bw`, `wl-paste` or `ssh`: the infra workspace reads your OpenSSH config and keys, and uses your `ssh-agent` when one runs, but never runs the `ssh` program.

## Install it

<Tabs>
<TabItem label="Nix">

Run it without installing:

```sh
nix run github:lfdominguez/desk
```

Or add it to your flake:

```nix
inputs.desk.url = "github:lfdominguez/desk";
# …
environment.systemPackages = [ inputs.desk.packages.${pkgs.system}.default ];
```

The flake builds for `x86_64-linux`, `aarch64-linux` and `aarch64-darwin` (Apple silicon; nixpkgs no longer builds for Intel Macs, so take the macOS download there). A flake build reports its version as `dev-<commit>`. On macOS it is the bare `desk` binary, not `desk.app`, so it shows no notifications: macOS only delivers them to an app bundle.

**Off NixOS** (Ubuntu, Fedora…), nixpkgs' graphics libraries can't find your system's GPU driver: they only look in `/run/opengl-driver`. When that folder is missing, the `desk` wrapper points them at nixpkgs' own Mesa instead. That covers Intel, AMD and nouveau; anything else (NVIDIA's own driver, for example) gets llvmpipe, Mesa's software renderer. If you set `__EGL_VENDOR_LIBRARY_FILENAMES`, `LIBGL_DRIVERS_PATH` or `GBM_BACKENDS_PATH` yourself, your value wins. See [Troubleshooting](/reference/troubleshooting/#nix-run-off-nixos).

</TabItem>
<TabItem label="AppImage">

Download `desk-<version>-x86_64.AppImage` from the [latest release](https://github.com/lfdominguez/desk/releases/latest), then:

```sh
chmod +x desk-*-x86_64.AppImage
./desk-*-x86_64.AppImage
```

</TabItem>
<TabItem label="Debian / Ubuntu">

Download `desk_<version>_amd64.deb` from the [latest release](https://github.com/lfdominguez/desk/releases/latest), then:

```sh
sudo apt install ./desk_<version>_amd64.deb
```

It pulls in the Wayland, EGL, xkbcommon and PipeWire libraries it needs. Claude Code and `bwrap` you install yourself.

</TabItem>
<TabItem label="Arch Linux (AUR)">

```sh
yay -S desk-kanban
```

Or with `paru`, or by hand:

```sh
git clone https://aur.archlinux.org/desk-kanban.git
cd desk-kanban
makepkg -si
```

It builds the tagged release from source and installs `desk`. The AUR's own `desk` package is another program (a shell workspace manager), so the two conflict. Claude Code is the AUR's `claude-code`; `bubblewrap` and `openssh` are listed as optional dependencies.

</TabItem>
<TabItem label="macOS">

Download `desk-<version>-macos.zip` from the [latest release](https://github.com/lfdominguez/desk/releases/latest). It holds `desk.app`, one universal app for Apple silicon and Intel. Unzip it and move it to Applications:

```sh
unzip desk-*-macos.zip
mv desk.app /Applications/
```

The app is not signed with an Apple Developer ID, so the first time Gatekeeper says it "cannot be opened because Apple cannot check it". Right-click `desk.app` in Finder, choose **Open**, then **Open** again; after that it opens normally. Or clear the download's quarantine flag once:

```sh
xattr -dr com.apple.quarantine /Applications/desk.app
```

`desk --version` and the other subcommands are the app's binary: `/Applications/desk.app/Contents/MacOS/desk --version`. Link it onto your `PATH` if you want the short name (`ln -s /Applications/desk.app/Contents/MacOS/desk ~/.local/bin/desk`).

What stays Linux-only: the infra workspace's virtual camera (sharing a terminal as a webcam needs PipeWire and v4l2loopback). Everything else works the same; desk keeps its files in the same places as on Linux, `~/.config/desk` and `~/.local/share/desk`.

</TabItem>
<TabItem label="Windows">

Each release has two Windows downloads on the [latest release](https://github.com/lfdominguez/desk/releases/latest), for x64:

- **`desk-<version>-windows-amd64.msi`**, the installer. Run it and accept the license: **Install** puts `desk.exe` in `%LOCALAPPDATA%\Apps\desk` for you alone, with no administrator rights; **Advanced** installs it for everyone in `C:\Program Files\desk` (asking for administrator rights once), lets you pick another folder, and leaves out the desktop shortcut if you untick it. Either way the folder goes on your `PATH` (the system's, for everyone), **desk** goes in the Start Menu and on the desktop, and the last page offers to launch it. If desk is already installed for everyone (as every MSI before this wizard did), the wizard picks that again, so the new version replaces it. A newer MSI replaces the installed version; uninstall it from **Settings → Apps**. Silent install, for you: `msiexec /i desk-<version>-windows-amd64.msi /qn`; for everyone: add `ALLUSERS=1`.
- **`desk-<version>-windows-amd64.zip`**, portable: `desk.exe`, the license and a short README. Unzip it anywhere and run `desk.exe`; nothing is installed.

Neither is code-signed yet, so the first time SmartScreen says "Windows protected your PC". Click **More info**, then **Run anyway**; after that it opens normally.

The infra workspace's card sessions run `desk peer`. desk puts its own folder first on the `PATH` of everything it starts, so that works from the zip too. To type `desk` in your own terminal, the MSI adds it to `PATH`; with the zip, add its folder yourself.

What's different on Windows: terminals run on ConPTY, and local shells are PowerShell 7 (`pwsh`) when it's installed, else Windows PowerShell. Claude Code is found on `PATH`, else at its installer's `%USERPROFILE%\.local\bin\claude.exe`, so a desk started from the Start menu finds it even before `PATH` has it (the Claude desktop app's own `claude.exe` is never used). An organization's Claude profile is handed to Claude Code as `CLAUDE_CONFIG_DIR`. desk keeps its files in the same layout as on Linux, under your user folder: `%USERPROFILE%\.config\desk` and `%USERPROFILE%\.local\share\desk`. The infra workspace's virtual camera stays Linux-only.

No winget or Scoop package yet.

</TabItem>
<TabItem label="From source">

**Linux:** you need Go (the version in `go.mod`), cgo, and the Wayland, xkbcommon, EGL and PipeWire headers:

```sh
git clone https://github.com/lfdominguez/desk.git
cd desk
CGO_CFLAGS_ALLOW=-fno-strict-overflow go build -tags nox11 -o desk ./cmd/desk
```

With Nix, `nix develop` gives you a shell with all of that. See [Development](/reference/development/).

**macOS:** you need Go and the Xcode command line tools (`xcode-select --install`), nothing else. Build `desk.app` (universal, ad-hoc signed) and its zip into `dist/`:

```sh
git clone https://github.com/lfdominguez/desk.git
cd desk
packaging/macos/build-app.sh
```

`ARCHS=arm64` builds only your Mac's architecture, which is faster; `VERSION=…` stamps a version. A plain `go build -tags nox11 -o desk ./cmd/desk` works too, but only the app shows notifications.

**Windows:** you need only Go; desk needs no cgo there. In PowerShell:

```powershell
git clone https://github.com/lfdominguez/desk.git
cd desk
go build -tags nox11 -ldflags "-H windowsgui" -o desk.exe ./cmd/desk
```

`-H windowsgui` keeps a console window from opening behind desk's. The release's zip and MSI (with the icon and version info in `desk.exe`) are cross-built from Linux by `packaging/windows/build.sh`; see [Development](/reference/development/#releases).

</TabItem>

## Releases and nightly

Releases are dated, not numbered: `2026.11.03`, and a second one the same day `2026.11.03.1`, then `.2`… Each one publishes a `.deb`, an AppImage, the macOS zip and the Windows MSI and zip on the [releases page](https://github.com/lfdominguez/desk/releases), and updates the AUR package.

Every push to `main` also replaces the [`nightly` pre-release](https://github.com/lfdominguez/desk/releases/tag/nightly): a `.deb`, an AppImage, a macOS zip and the Windows MSI and zip of that commit. Its version reads like `2026.11.04~git1a2b3c4`. Use it to try what's coming; use a dated release otherwise.

To see which version you run:

```sh
desk --version
```

The Settings show it too, at the bottom of their left column.
